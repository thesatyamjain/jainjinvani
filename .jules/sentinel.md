## 2025-02-12 - Hardcoded 2FA Secret Key in Source Code
**Vulnerability:** Found a hardcoded 2FA secret (`JINVANISACRED26A`) being exported as a constant in `src/pages/AdminLogin.tsx`. This causes all instances of the application to share the same TOTP secret.
**Learning:** Hardcoded secrets, even those intended to be used as 'templates' or 'defaults' in static client-side apps, create a fundamental security vulnerability because any user with access to the code can generate valid 2FA tokens. In a purely client-side setup without a backend DB, secrets must be securely and dynamically generated in the browser using cryptographic methods (`window.crypto.getRandomValues`).
**Prevention:** Avoid defining security keys as static variables. Instead, use a singleton function to lazily generate and persist a secure key using `localStorage`. When migrating away from a hardcoded secret in production environments, always check for the legacy configuration to maintain backward compatibility and avoid locking out active users who initialized their accounts with the hardcoded string.

## 2025-02-13 - Hardcoded Recovery Codes and Hashes in UI
**Vulnerability:** Emergency offline recovery codes (`JIN-8492-SAFE`) and their corresponding static SHA-256 hashes were hardcoded directly in the frontend UI (`AdminLogin.tsx`).
**Learning:** Hardcoding backup recovery codes in a client-side bundle is a critical security risk because anyone examining the application source can discover the fallback passwords. Trying to dynamically generate these via `localStorage` is also flawed since recovery codes are specifically meant to bypass local device state loss.
**Prevention:** For offline/cross-device secrets like emergency recovery codes in a serverless app, avoid generating them into `localStorage`. Store their cryptographic hashes securely in environment variables (e.g., `VITE_RECOVERY_HASHES`) instead. Never render plaintext default secrets in the UI. Instead, provide instructional text directing administrators to their secure vaults (e.g. `.env`).
