## 2024-05-16 - Dynamic 2FA Secret Generation for Client-Side Admin Login
**Vulnerability:** A hardcoded `MASTER_2FA_SECRET` ('JINVANISACRED26A') was used for TOTP 2FA authentication in a purely client-side React app. Since the client-side code is fully exposed, anyone could extract this secret and bypass the 2FA protection, rendering it useless.
**Learning:** In a client-side architecture without a backend for authentication, deterministic shared secrets provide false security. The 2FA secret must be uniquely and dynamically generated per instance (device/browser) and stored securely in local state (e.g., `localStorage`), rather than statically compiled into the source code.
**Prevention:** Always use secure random number generators (e.g., `crypto.getRandomValues`) to create unique initialization vectors or keys at runtime. Implement fallback logic to check client state to ensure backward compatibility for users who previously set up 2FA with the legacy hardcoded key. Never commit shared plaintext secrets for authentication to the repository.
